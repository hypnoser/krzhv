# Сайт krzhv.com.ua

Сайт побудований на Eleventy (11ty), хоститься на GitHub Pages, DNS і кешування — через Cloudflare. При кожному push у гілку `main` GitHub Actions автоматично збирає сайт і публікує зміни — за 1-2 хвилини вони з'являються на krzhv.com.ua.

Все керування контентом відбувається через звичайний веб-інтерфейс GitHub — термінал не потрібен.

------

## Загальні принципи

- Кожна стаття / пост блогу / квіз — окремий `.md`-файл з **метаданими** (текст між `---` на початку файлу) і самим текстом статті нижче
- Метадані визначають заголовок, опис, категорію, дату, шаблон оформлення (`layout`) — Eleventy автоматично перетворює файл на готову сторінку в дизайні сайту
- **Назва файлу може бути якою завгодно** (кирилицею, з пробілами) — для статей блогу адреса сторінки (URL) генерується автоматично з поля `title`, з транслітерацією в акуратний латинський вигляд. Для статей `/statti/` адреса генерується з назви файлу — тому файли статей варто називати латиницею (напр. `depresiya.md`)
- Після будь-якої зміни файлу натисни **Commit changes** внизу сторінки редагування GitHub
- `sitemap.xml`, `robots.txt`, `llms.txt` оновлюються повністю автоматично, вручну нічого редагувати не потрібно

## Статті для клієнтів (`/statti/`)

### Додати нову статтю

1. Відкрий папку `src/statti/` у репозиторії на GitHub
2. **Add file → Create new file**
3. Назви файл латиницею без пробілів, напр. `vyhorannya.md` — саме ця назва стане частиною адреси сторінки (`/statti/vyhorannya/`)
4. Встав на початку файлу метадані:

```
---
layout: article.njk
title: "Заголовок статті"
description: "Короткий опис для пошукових систем (1-2 речення)"
category: "Категорія"
date: 2026-08-20
section: statti
sectionLabel: "Матеріали"
sources:
  - "Джерело 1"
  - "Джерело 2"
---
```

**Важливо:** для статей у `/statti/` завжди вказуй `layout: article.njk` (не `blog-post.njk` — це шаблон для іншого розділу, блогу, і переплутати їх легко, якщо копіювати метадані з іншого файлу).

**Чинні категорії** (для них уже намальовані власні кольорові іконки — вкажи назву точно так, і іконка підхопиться автоматично): `Тривожні розлади`, `Настрій`, `ОКР`, `Тіло і стрес`, `Сон`. Інша назва — стаття все одно опублікується, просто з нейтральною іконкою.

5. Нижче метаданих пиши текст статті звичайним Markdown:
   - `## Заголовок` — підзаголовок розділу
   - `**жирний текст**`
   - `- пункт списку`
   - `> цитата` — оформляється як виділена цитата курсивом
   - Таблиці — звичайний Markdown-синтаксис (`| колонка 1 | колонка 2 |`)
   - Зображення — використовуй прямий HTML-тег, не Markdown-синтаксис `![]()`, щоб вказати розмір і уникнути спотворення макета під час завантаження:
     ```
     <img src="/assets/images/statti/vyhorannya/photo.jpg" alt="Опис зображення" width="720" height="400" style="max-width:100%;height:auto;">
     ```
     Спочатку завантаж саме зображення в папку `src/assets/images/statti/<slug статті>/` через **Add file → Upload files**. **Шлях завжди починай з `/assets/...` (з похилою рискою спочатку), не `../assets/...`** — відносний шлях ламається через глибину вкладеності сторінки.

6. **Commit changes**

### Редагувати чи видалити статтю

Відкрий потрібний `.md`-файл у `src/statti/`, натисни іконку олівця (Edit) для редагування, або кошик/"Delete file" для видалення. **Commit changes**.

## Блог (`/blog/`)

Той самий процес, файли в папці `src/blog/`. Метадані:

```
---
layout: blog-post.njk
title: "Заголовок посту"
description: "Короткий опис"
audience: colleagues
date: 2026-08-20
---
```

**Важливо:** для постів блогу завжди вказуй `layout: blog-post.njk` (не `article.njk`).

Адреса сторінки блог-посту генерується автоматично з поля `title` — не потрібно думати про назву файлу чи вручну транслітерувати заголовок, сайт зробить це сам. Файл можна називати як завгодно, хоч кирилицею.

`audience` визначає кольорову мітку посту:
- `colleagues` — мітка "Для колег" (теракотовий колір)
- `journal` — мітка "Журнал" (шавлієвий колір)

Додавання зображень, редагування і видалення — так само, як для статей.

## Опитувальники (`/kviz/`)

Три науково валідовані скринінгові опитувальники (тривога — GAD-7, депресія — PHQ-9, панічні атаки — власний скринінг на основі DSM-5), файли `src/kviz/tryvoga.md`, `src/kviz/depresiya.md`, `src/kviz/panichni-ataky.md`.

Тексти запитань, шкали балів, описи результатів і **кризова логіка** (автоматичний показ контактів і гарячої лінії при відповідях, що вказують на ризик) — усе технічно редагується так само, через ці файли. Але зміну структури питань, порогових балів чи кризової логіки **краще узгоджувати окремо** — тут є клінічна й юридична чутливість.

## Відгуки (`/vidguky/`)

Один спільний файл: `src/_data/testimonials.json`. Додати новий відгук — новий блок у масиві:

```json
{
  "text": "Текст відгуку клієнта",
  "who": "Клієнтка, 30 років",
  "topic": "Тривога"
}
```

**Чинні теми** (з кольоровими іконками): `Тривога`, `Депресія`, `Панічні атаки`. Інша назва — без спеціальної іконки.

На головній сторінці показуються перші 3 відгуки зі списку, на `/vidguky/` — усі. Найновіші варто додавати на початок списку. Слідкуй, щоб після кожного блоку `{ ... }`, крім останнього, стояла кома — це вимога формату JSON.

## Закрити сайт (накладка)

Прапорець `closed` у `src/_data/siteStatus.json`: `true` показує на **всіх** сторінках (крім `/secret/`) екран «Сайт тимчасово закрито» з email і номерами 103/112; `false` — сайт відкритий. Змінити одне слово на GitHub (олівець біля файлу → `true`/`false` → Commit), деплой за 1–2 хв. Інструкція і кнопка-посилання на файл — на сторінці `/secret/admin/` (після входу в `/secret/`).

- Накладка лише візуальна: HTML сторінок не змінюється, пошуковики й боти бачать те саме, що й люди (без окремого показу ботам). Код 503 на GitHub Pages віддати неможливо.
- Невидимий клік у правому верхньому куті екрана накладки відкриває сайт у цьому браузері (прапорець `krzhv_maintenance_bypass` у localStorage; діє на всі сторінки, скидається очищенням даних сайту). Це зручність для власника, а не захист.
- Текст накладки — у `src/_layouts/base.njk` (блок «Накладка «сайт закрито»»).
- Блокування РФ/БР робиться в Cloudflare (WAF → правило «BLOCK RU BY») і від накладки не залежить.

## Закритий розділ (`/secret/`)

Сторінка https://krzhv.com.ua/secret/ — вхід за паролем і список закритих файлів. Пароль вводиться один раз на браузер (ключ зберігається в localStorage; «Вийти на цьому пристрої» — стирає). Сторінки немає в меню, sitemap, llms.txt; закрита від індексації.

**Репозиторій публічний, тому файли в `src/secret/files/` лежать лише в зашифрованому вигляді (AES-GCM, ключ з пароля через PBKDF2).** Оригінали в репозиторій не завантажувати.

### Додати файл (.html або .md)

1. Відкрити `/secret/`, увійти, розгорнути «Додати файл».
2. Обрати файл, вказати назву, опис, дату, за потреби — групу (файли однієї групи показуються в спільному блоці; нумерація в групі ставиться автоматично) → «Зашифрувати і завантажити». Браузер збереже зашифрований `.html`.
3. На GitHub: `src/secret/files/` → Add file → Upload files → перетягнути файл → Commit changes.
4. За 1–2 хвилини файл з'явиться в списку. Адреса: `/secret/files/<ім'я>.html` — теж відкривається лише з паролем.

Markdown перетворюється в HTML під час шифрування (нейтральне оформлення, не стиль сайту).

### Видалити чи замінити файл

Видалити — видалити файл у `src/secret/files/` на GitHub. Замінити — зашифрувати нову версію з тим самим ім'ям і завантажити поверх.

### Змінити пароль

Пароль не зберігається в репозиторії: у `src/assets/js/secret.js` є лише сіль (`SALT`) і контрольний шифротекст (`VERIFIER`). Зміна пароля = нові `SALT`/`VERIFIER` (згенерувати скриптом) + перешифрувати всі файли з оригіналів. Тож оригінали зберігайте у себе.

## Статистика відвідувань (`/secret/analytics/`)

Закрита сторінка з панеллю: перегляди й візити, країни, джерела (пошук, соцмережі, ШІ-асистенти, прямі), переходи між сторінками, час доби, пристрої, Core Web Vitals, сирі дані з CSV-вивантаженням, фільтри (період, країна, пристрій, джерело, сторінка, «звідки», браузер, ОС) з виключенням, порівняння з попереднім періодом. Адресу фільтрів можна зберегти в закладці (стан у `#`). `?demo` після входу показує панель на згенерованих даних.

**Звідки дані.** Лічильник сайту — Cloudflare Web Analytics (маяк додається Cloudflare автоматично; siteTag для GraphQL скрипт визначає сам за доменом, або задайте секрет `CF_SITE_TAG`). Під час кожного деплою і щогодини (cron у `.github/workflows/deploy.yml`) скрипт `scripts/fetch-analytics.js` бере агрегати з GraphQL API Cloudflare (за 180 днів), стискає (gzip), шифрує ключем розділу `/secret/` і кладе як `/secret/analytics/data.json`. У репозиторії даних немає; без пароля файл — набір байтів. Усе фільтрування й графіки — у браузері.

**Одноразове налаштування** (GitHub → Settings → Secrets and variables → Actions → New repository secret):

| Секрет | Що це |
|---|---|
| `CF_ANALYTICS_TOKEN` | Cloudflare → My Profile → API Tokens → Create Token → Custom, дозвіл **Account · Account Analytics · Read** |
| `CF_ACCOUNT_ID` | Cloudflare → Overview будь-якого домену → правий стовпчик → Account ID |
| `SECRET_PASSWORD` | той самий пароль, що й для входу в `/secret/` (з нього скрипт виводить ключ шифрування) |

Потім Actions → «Build and deploy site» → Run workflow. Без секретів збірка не ламається: скрипт лише попереджає, а сторінка покаже підказку з налаштування. **Після зміни пароля `/secret/` оновіть `SECRET_PASSWORD`**, інакше сторінка напише, що знімок не розшифровується.

**Фільтр ботів (лише на екрані).** Cloudflare віддає агрегати, тому окремих запитів немає; сирі дані ніде не відкидаються й не змінюються, фільтр діє тільки в `/secret/analytics/` (`classifyBots` в `analytics.js`). Перемикач «Боти: усі / без явних / суворо» (за замовчуванням «без явних») й картка з оцінкою та списком того, що відсіюється (топ-10 груп, видно правило, країну, ОС/браузер, сторінку). Правила: (1) явні: UA/ОС з ознаками автоматизації (headless, bot, crawler, python, curl тощо); підозрілі: (2) Linux-десктоп без джерела, (3) хвилі без джерела з однієї країни за годину (≥12 переглядів, ≥90% десктоп, 1-2 сторінки), (4) попередня підгрузка (prerender), (5) ідеально регулярні візити: однакова година/країна/сторінка/ОС/браузер без джерела з майже однаковою кількістю щодня ≥14 діб. Це оцінка, а не доказ: хибні групи видно в списку й їх можна повернути режимом «усі дані» чи фільтром країни/ОС/сторінки. Облік на сайті (маяк Cloudflare) не змінювався.

**Власні візити не рахуються.** На пристрої, де виконано вхід у `/secret/`, звіти маяка Cloudflare (`/cdn-cgi/rum`) не відправляються — скрипт у `<head>` (`src/_layouts/base.njk`), прапорець `krzhv-noanalytics` у localStorage. На інших пристроях (напр. телефон без входу) — один раз відкрити `https://krzhv.com.ua/?noanalytics=1`; повернути облік — `?noanalytics=0` або галочка на сторінці статистики. Минулі візити з даних прибрати не можна (Cloudflare віддає лише агрегати).

**Обмеження даних Cloudflare.** Вибірка (≈1 з 10, значення вже перераховані); немає тривалості перебування, відсотка відмов і сторінки виходу; «з якої на яку» — лише переходи всередині сайту (за реферером). Власні заходи в `/secret/` теж рахуються, тому панель за замовчуванням їх ховає (галочка «без /secret/»). Cron GitHub вимикається після 60 днів без активності в репозиторії; увімкнути знову — вкладка Actions. Точна тривалість потребувала б власного збирача (напр. Cloudflare Worker) і оновлення політики конфіденційності — зараз не реалізовано.

**Вкладка «Сервер (без JS)».** Лічильник Web Analytics — це JavaScript у браузері відвідувача, тому його не бачать блокувальники реклами, режими приватності (напр. iPhone із захистом від відстеження, VPN) та ті, хто закрив сторінку до відправки даних. Тому знімок додатково бере **журнал запитів Cloudflare** (HTML-сторінки за 14 днів, агреговано по годинах: країна, пристрій, браузер, сторінка; без IP) і відсіює боти за правилами `scripts/bot-rules.js`: відомі роботи (пошукові, AI, SEO, прев'ю посилань, моніторинг, сканери, скрипти), порожні й підроблені User-Agent, хвилі запитів із одного пристрою (багато різних сторінок за годину). Три рівні: «людина», «підозріло» (окремо, у «людей» не входить), «бот». Позначка «Скрипти: так» — пристрій завантажив скрипти сайту (майже напевно браузер людини). Вкладка не змінює основні графіки: ті лишаються даними JS-лічильника.
Налаштування: додайте токену `CF_ANALYTICS_TOKEN` право **Zone · Analytics · Read** для зони сайту (до наявного Account Analytics · Read). Ідентифікатор зони `krzhv.com.ua` зашито за замовчуванням; для іншого домену задайте секрет/змінну `CF_ZONE_ID`. `EDGE=0` вимикає вкладку, `EDGE_DAYS` змінює глибину (1–30 днів). Без права скрипт лише попередить, а решта статистики працює. Тести правил (симуляції ботів і людей, зокрема реальні рядки з журналу сайту): `node scripts/test-bot-rules.js` (входить у `npm test`). Нових ботів додавайте в `RULES` у `scripts/bot-rules.js` і в тест.

### Пошукові запити (вкладка «Запити», Google Search Console)
Referer від Google не містить запиту, тому запити беруться з Search Console (`scripts/gsc.js`, тест `scripts/test-gsc.js`). Секрети Actions: `GSC_KEY` (весь JSON-ключ сервісного акаунта Google, права лише читання) і `GSC_SITE` (`sc-domain:krzhv.com.ua` для доменного ресурсу або `https://krzhv.com.ua/` для префікса URL). E-mail сервісного акаунта додається в Search Console → Налаштування → Користувачі й дозволи з правом «Обмежений». Глибина: `GSC_DAYS` (за замовчуванням 90). Без секретів вкладка покаже інструкцію, решта статистики працює. Запити зі штучних асистентів (ChatGPT тощо) недоступні: сайту передається лише реферер.
Обмеження: у журналі немає джерела переходу (referrer) і IP, тому відсіювання за User-Agent та поведінкою наближене. Один і той самий User-Agent у багатьох людей (скорочений UA Chrome на Android, iPhone) не рахується ботом лише через велику кількість запитів на одну сторінку. Серверні дані зберігаються стільки, скільки тримає Cloudflare (не менше 14 днів); щогодинний знімок їх перезаписує.

**Мітки джерела в посиланнях на бота.** Усі посилання на `t.me/krzhv_bot` ведуть із міткою `?start=site_<сторінка>_<місце>` (фільтр `botLink` у `eleventy.config.js`; у квізі — `kviz.js`). Бот записує мітку в колонку «Джерело» таблиці, тож видно, з якої сторінки й кнопки прийшов клієнт, навіть якщо лічильник відвідувача заблоковано. Дозволені символи мітки Telegram: латиниця, цифри, `_`, `-`, до 64 знаків.

## Заглушка "Сайт на реконструкції"

Якщо потрібно тимчасово показати відвідувачам головної сторінки повідомлення "Сайт на реконструкції" (решта сторінок сайту продовжує працювати як завжди, і пошукові системи як і раніше бачать і індексують реальний контент):

- **Увімкнути:** у файлі `src/index.njk` додай рядок `maintenanceOverlay: true` у метадані вгорі файлу
- **Вимкнути:** видали цей рядок

У правому верхньому куті заглушки є невидима клікабельна зона (48×48 пікселів) — клік по ній ховає заглушку саме в цьому браузері (запам'ятовується постійно, аж доки не очистиш дані сайту в браузері вручну).

## Дизайн, favicon, шрифти

- Кольори, типографіка, всі стилі сайту — `src/assets/css/style.css`. Він вбудований прямо в кожну сторінку (не окремий файл) для швидкості завантаження
- Шрифти (Merriweather, Inter) розміщені на самому сайті (не завантажуються з Google) — файли в `src/assets/fonts/`
- Favicon (іконка сайту у вкладці браузера) — файли в `src/static/`

Зміни в дизайні, структурі головної сторінки чи нові секції — глибші правки, для них краще звертатись окремо, щоб не порушити верстку.

## Поширені помилки

- **Переплутаний `layout`** — стаття в `/statti/` з `layout: blog-post.njk` або пост блогу з `layout: article.njk` призведе до неправильної адреси сторінки чи поламаного оформлення
- **Забуті лапки в метаданих** (`title: Заголовок` замість `title: "Заголовок"`) — завжди бери текст у лапки, особливо якщо в ньому є двокрапка чи спецсимволи
- **Відносний шлях до зображення** (`../assets/...`) — завжди використовуй абсолютний (`/assets/...`)
- **Забута кома в JSON** (відгуки) — після кожного блоку `{ ... }`, крім останнього в списку, має стояти кома
- **Дата в неправильному форматі** — завжди `РРРР-ММ-ДД`, наприклад `2026-08-20`

Якщо після Commit сайт не оновився чи виглядає зламаним — зайди у вкладку **Actions** на GitHub і подивись, чи є червоний хрестик (помилка збірки). Скопіюй текст помилки — розберемось.


`npm test` автоматично запускається на GitHub перед публікацією (workflow «Build and deploy site») і для кожного PR (workflow «Check site»). Якщо в статті бите посилання, публікація зупиниться — у вкладці **Actions** буде видно, яке саме.

## Технічні нотатки

- **Шрифти** в `src/assets/fonts/` урізані до латиниці й кирилиці (≈270 КБ замість ≈730 КБ). Якщо замінюєте файл шрифту — так само уріжте його (fontTools `pyftsubset`), інакше сторінки знову сповільняться.
- **Стилі** зі `style.css` вбудовуються в кожну сторінку в стиснутому вигляді. Стилі й скрипти, що підключаються файлами, отримують `?v=<хеш>` автоматично — після зміни браузери не беруть стару версію.
- **Статистика** — лише Cloudflare Web Analytics (без cookies, вмикається в Cloudflare, у коді сайту нічого немає). Google Analytics прибрано 20.10.2026.
- **Стрічка** `/feed.xml` (Atom): 20 найновіших статей і постів, будується автоматично.
- **Прев'ю для соцмереж** `src/assets/images/og-image.jpg` генерується з `scripts/og/og-image.html`: змініть текст і запустіть `python3 scripts/og/render.py`.
- **Перевірка статей.** Поле `reviewed: РРРР-ММ-ДД` — дата, коли джерела статті звірено. Показується під заголовком і йде в розмітку як `lastReviewed`. `npm test` попереджає, якщо дати немає, якщо вона старша за 12 місяців або якщо джерела записані рядком без посилання.
- **Чернетки.** Щоб зняти пост з публікації, не видаляючи файл: `permalink: false` і `eleventyExcludeFromCollections: true` (приклад — `src/blog/_chernetka-hormony-shchastia.md`).
- **Стаття поза компетенцією** (напр., ПТСР): поле `referOut: "текст"` замінює заклик «Записатись» у кінці статті на скерування.
- **Блок контактів «Зробіть перший крок»** на сторінках з `layout: static.njk` показується за замовчуванням; прибрати — `showContact: false`.
- **Зображення** в тексті статей автоматично отримують відкладене завантаження (`loading="lazy"`).

## Кеш Cloudflare

Сайт віддається через Cloudflare. Правила кешу (Cloudflare → krzhv.com.ua → Caching → Cache Rules):

| Що | Cloudflare | Браузер |
|---|---|---|
| Сторінки, sitemap, robots, llms.txt | 10 хв | 10 хв (як задає GitHub Pages) |
| `/assets/css/`, `/assets/js/`, `/assets/fonts/` | 1 рік | 1 рік |
| `/assets/images/`, `/assets/icons/` | 1 доба | 1 доба |

- Стилі й скрипти отримують `?v=<хеш>` автоматично, тож після змін завантажуються нові.
- **Шрифти** кешуються на рік без версії в адресі. Якщо колись заміните файл шрифту — дайте йому нову назву (і оновіть `@font-face` у `style.css`) або очистіть кеш Cloudflare.
- Нову версію зображення з тією ж назвою відвідувачі побачать протягом доби. Щоб одразу: Cloudflare → Caching → Configuration → **Purge Cache**.
- Автоматичне очищення кешу після публікації вмикається секретами репозиторію `CLOUDFLARE_API_TOKEN` (права Zone → Cache Purge, без терміну дії) і `CLOUDFLARE_ZONE_ID` (Settings → Secrets and variables → Actions). Без них крок у workflow просто пропускається.
- `www.krzhv.com.ua` переадресовується на `krzhv.com.ua` (Rules → Redirect Rules).
