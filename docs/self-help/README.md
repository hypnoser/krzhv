## Результат перевірки джерел і редактури

Джерела перевірено 30 вересня 2026 року після застосування мережевих налаштувань. Рекомендації тепер мають прямі посилання на відповідні сторінки та розділи; непідтверджені відсотки й терміни гарантованого одужання вилучено. Нових чисел ефективності немає.

- **Панічні атаки:** прямі джерела невідкладних ознак і 103, непримусове дихання, заземлення як авторське скорочення підходу ВООЗ, поступові побутові кроки з посиланням NHS; відсутність універсальної гарантії безпеки.
- **Депресія:** точні посилання Cochrane та COBRA з межами перенесення результатів курсів терапії на домашні кроки; пряме джерело підтримки при суїцидальних думках.
- **Постійна тривога:** джерело симптомів, відмінність прикладу NHS від протоколу дослідження відкладання хвилювання, поступова робота із зайвими запевненнями та межі самодопомоги.
- **Пов’язані статті:** виправлена бібліографія Dugas 1998 і 2022; прибрані непідтверджені записи й невідповідне посилання на дослідження молоді для тверджень про дорослих. Пом’якшені твердження про кортизол і нервову систему, виправлена реальна проблема з дією пізніше. Ілюстрації з непідтвердженими поясненнями прибрані з цих статей; файли ресурсів збережені.
- **Контакти:** 103 і 112 підтверджено статтею 4 українського закону. Прибрано неперевірені в цьому пакеті згадки 102 та закордонних 112/911; за кордоном зазначено місцеву екстрену службу. Lifeline прямо позначено як призупинений оператором. Для 2345 наведено призначення, аудиторію, географію та графік з офіційної сторінки. Для лінії щодо домашнього насильства залишено посилання на оператора: години в прочитаній основній сторінці не вказані.

NICE CG113 потребує оновлення за рішенням перегляду від 11.09.2026; настанова не названа оновленою у 2026 році. NHS Panic disorder має прострочену планову дату перегляду — це позначено у звіті. Субдомен допомоги НПА залишається недоступним через проксі; неперевірені контакти НПА не додані. Доступність телефонів фактичним дзвінком не тестувалася.

## Клінічні рішення власника

Рутинну редактуру вже виконано. Після перевірки джерел залишаються три рішення щодо меж матеріалу під ім'ям власника:

1. **Медична безпека при паніці.** Прийняти формулювання: «Наведені невідкладні ознаки — приклади, а не повний перелік. За описом у статті не можна виключити медичну причину; нові або незвичні симптоми потребують оцінки». За потреби посилити вимогу оцінки, без категоричного заспокоєння.
2. **Поведінкові кроки без супроводу.** Поточний варіант обмежено повсякденними безпечними діями після оцінки нападів, без самостійної провокації симптомів. Консервативніший варіант: «Якщо ви не впевнені в безпеці ситуації або симптомів, плануйте повернення до справ лише з фахівцем».
3. **Межі посібника при депресії.** Залишити негайне звернення при загрозі життю та швидку професійну оцінку при думках про смерть, без вимоги чекати вправ чи двох тижнів. Посильний мінімум і записи — підтримка, не заміна лікування чи контроль успішності пацієнта.

## PR, публікація та відкат

PR відкривається з гілки `codex/self-help-guides` до `main`. Команда для створення PR із підготовленим описом:
```bash
gh pr create --repo hypnoser/krzhv --base main --head codex/self-help-guides \
  --title 'Додати три посібники самодопомоги в Матеріали' \
  --body-file docs/self-help/PR.md
```

Погоджені виправлення включено до комітів. Останній commit змінює тільки `src/index.njk`: видаляє `maintenanceOverlay: true`. Посилання на створений PR і його фактичний стан агент надає в чаті; наявність `PR.md` сама по собі не означає публікацію. Workflow публікації налаштований на push у `main` або ручний запуск; push робочої гілки й відкриття PR не публікують сайт.

Порядок запуску для власника:

1. Переглянути результат перевірки джерел і клінічні межі вище; після створення PR перевірити його актуальний опис і результати перевірок. Єдине рішення про запуск — **злити чи відкласти весь пакет**. До погодження власником публікацію не виконувати.
2. Перед злиттям записати фактичний SHA поточного `main` (він може змінитися після початкової бази). Перевірити diff PR й окремий останній commit заглушки.
3. Злити PR до `main`. Не запускати production вручну з робочої гілки. Наявний GitHub Actions `Build and deploy site` виконає build і deploy після push у `main`.
4. Дочекатися зелених **обох** jobs у [GitHub Actions](https://github.com/hypnoser/krzhv/actions), перевірити опублікований commit. Не видавати локальну збірку за успіх deployment.
5. Перевірити живі `/statti/`, три погоджені адреси, перехід із головної до `#samodopomoha`, відсутність заглушки, canonical/JSON-LD/sitemap та `noindex` навчальних матеріалів. Перевірити з чистого браузера, без локального обходу заглушки.
6. При проблемі відкотити через **revert**, а не reset/force push. Для merge commit: нова гілка від поточного main, `git revert -m 1 <merge_sha>` і PR відкату. Для squash: `git revert <squash_sha>`. Для rebase: revert комітів пакета від останнього до першого. Відкат усього пакета також поверне `maintenanceOverlay: true`. Дочекатися deployment відкату й повторити перевірку живого сайту.

## Search Console після успішної публікації

Доступ не надано; жодних запитів індексації чи змін інтеграцій не виконано.

1. Власник відкриває наявну властивість `krzhv.com.ua` зі своїм доступом; не змінює права інтеграцій.
2. У URL Inspection перевіряє нову `/statti/postiina-tryvoha/` та дві збережені адреси. Виконує Live Test, звіряє HTTP 200, canonical та доступність індексації.
3. Після успішного live test може запросити індексацію цих URL. Це запит, а не гарантія індексації чи позицій.
4. Перевіряє обробку `https://krzhv.com.ua/sitemap.xml` у Sitemaps; за потреби повторно надсилає наявну карту. Навчальні `noindex`-матеріали не надсилає на індексацію.
5. Згодом перевіряє Page indexing і вибраний Google canonical. Жодних заяв про частотність, трафік або SEO-результат без фактичних даних.
