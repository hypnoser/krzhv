## Клінічні рішення власника

Рутинну редактуру вже виконано. Після завершення агентом фактчекінгу залишаються три рішення щодо меж матеріалу під ім'ям власника:

3. **Межі посібника при депресії.** Залишити негайне звернення при загрозі життю та швидку професійну оцінку при думках про смерть, без вимоги чекати вправ чи двох тижнів. Посильний мінімум і записи — підтримка, не заміна лікування чи контроль успішності пацієнта.

## PR, публікація та відкат

До відновлення доступу GitHub API PR не можна підтвердити. Якщо гілка успішно відправлена, відкриття PR з CLI:

```bash
gh pr create --repo hypnoser/krzhv --base main --head codex/self-help-guides \
  --draft --title 'Додати три посібники самодопомоги в Матеріали' \
  --body-file docs/self-help/PR.md
```

Поки джерела не прочитані, PR має залишатися чернеткою. Після усунення блокера агент має виконати перевірку, внести потрібні поправки, повторити збірку й браузерні перевірки, оновити опис PR та перевести його в готовий до перегляду стан. Вимкнення заглушки має залишитися окремим останнім commit.

Порядок запуску для власника:

1. Переконатися, що фактчекінг завершений і блокери з опису PR зняті; переглянути клінічні межі вище. Єдине рішення про запуск — **злити чи відкласти весь пакет**. Зараз рекомендація: відкласти.
2. Перед злиттям записати фактичний SHA поточного `main` (він може змінитися після початкової бази). Перевірити diff PR й окремий останній commit заглушки.
3. Злити PR до `main`. Не запускати production вручну з робочої гілки. Наявний GitHub Actions `Build and deploy site` виконає build і deploy після push у `main`.
4. Дочекатися зелених **обох** jobs у [GitHub Actions](https://github.com/hypnoser/krzhv/actions), перевірити опублікований commit. Не видавати локальну збірку за успіх deployment.
5. Перевірити живі `/statti/`, три погоджені адреси, перехід із головної до `#samodopomoha`, відсутність заглушки, canonical/JSON-LD/sitemap та `noindex` навчальних матеріалів. Перевірити з чистого браузера, без локального обходу заглушки.
6. При проблемі відкотити через **revert**, а не reset/force push. Для merge commit: нова гілка від поточного main, `git revert -m 1 <merge_sha>` і PR відкату. Для squash: `git revert <squash_sha>`. Для rebase: revert комітів пакета від останнього до першого. Відкат усього пакета також поверне `maintenanceOverlay: true`. Дочекатися deployment відкату й повторити перевірку живого сайту.
