# krzhv-mailer: модуль для наявного проєкту Apps Script

Файл `krzhv-mailer.gs` додається до проєкту, де вже працює Telegram-бот. Бот не змінюється: модуль має свої імена (префікс `krzhv`) і свої властивості скрипту.

## Підключення (див. покрокову інструкцію в чаті)
1. Новий файл `krzhv-mailer.gs` у проєкті, вставити вміст.
2. У `doPost(e)` першими рядками: `const krzhvRes = krzhvMailRoute_(e); if (krzhvRes) return krzhvRes;`
3. Властивості скрипту: `KRZHV_TOKEN`, `KRZHV_GH_TOKEN`, `KRZHV_GH_REPO`.
4. Один раз запустити `krzhvMailSetup`, надати дозволи.
5. Розгортання → Керувати → Редагувати наявне → Нова версія (адреса `/exec` не змінюється).
6. Змінні середовища агента: `KRZHV_MAIL_URL` (та сама адреса `/exec`, що в бота), `KRZHV_MAIL_TOKEN` (= `KRZHV_TOKEN`).

## Як це працює
- Агент: `mail.py send --kind draft --publish-file локальний=шлях/в/репо --publish-url ...` (`--publish-at` необов'язковий; без нього публікація одразу після «ОК»). До теми чернетки скрипт додає мітку часу, щоб нова версія не потрапила в стару гілку.
- Лист іде власнику, гілка отримує мітку `krzhv-draft`, тригер раз на 5 хвилин (постійний; відновлюється на кожен запит агента).
- Відповідь «ОК»: після `publishAt` скрипт сам комітить файли `src__*` з першого листа в `main` через GitHub API, ставить `krzhv-done`, одразу надсилає лист «Опубліковано в main» (з посиланнями на коміти), `date`/`updated`/`reviewed` у .md виставляє на день публікації, через ~4 хвилини перевіряє сторінку й надсилає «Сторінка відкривається» або «УВАГА».
- `mail.py status`: усі гілки за 14 днів (для перевірки, чи надійшла чернетка). `poll` повертає `isOk: true`, якщо публікація на «ОК» не вдалась (прийшов лист УВАГА): правок немає.
- Не видаляй листи `[krzhv]` до публікації: видалена (кошик) гілка ігнорується.
- Інша відповідь = правки: мітка `krzhv-edit`, їх підхоплює агент (`mail.py poll`), надсилає нову версію.
- Коли чекати нічого, тригер видаляється сам.
- Секрети лише у властивостях скрипту й середовищі, не в репозиторії й не в чаті.
