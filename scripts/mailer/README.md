# krzhv-mailer: модуль для наявного проєкту Apps Script

Файл `krzhv-mailer.gs` додається до проєкту, де вже працює Telegram-бот. Бот не змінюється: модуль має свої імена (префікс `krzhv`) і свої властивості скрипту.

## Підключення (див. покрокову інструкцію в чаті)
1. Новий файл `krzhv-mailer.gs` у проєкті, вставити вміст.
2. У `doPost(e)` першими рядками: `const krzhvRes = krzhvMailRoute_(e); if (krzhvRes) return krzhvRes;`
3. Властивості скрипту: `KRZHV_TOKEN`, `KRZHV_GH_TOKEN`, `KRZHV_GH_REPO`.
4. Один раз запустити `krzhvMailSetup`, надати дозволи.
5. Розгортання → Керувати → Редагувати наявне → Нова версія (адреса `/exec` не змінюється).
6. Змінні середовища агента: `KRZHV_MAIL_URL` (та сама адреса `/exec`, що в бота), `KRZHV_MAIL_TOKEN` (= `KRZHV_TOKEN`).

## Як це працює
- Агент: `mail.py send --kind draft --publish-file локальний=шлях/в/репо --publish-at ... --publish-url ...`.
- Лист іде власнику, гілка отримує мітку `krzhv-draft`, вмикається хвилинний тригер.
- Відповідь «ОК»: після `publishAt` скрипт сам комітить файли `src__*` з першого листа в `main` через GitHub API, ставить `krzhv-done`, через кілька хвилин перевіряє сторінки й надсилає лист «Опубліковано».
- Інша відповідь = правки: мітка `krzhv-edit`, їх підхоплює агент (`mail.py poll`), надсилає нову версію.
- Коли чекати нічого, тригер видаляється сам.
- Секрети лише у властивостях скрипту й середовищі, не в репозиторії й не в чаті.
